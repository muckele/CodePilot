# CodeLift AI v0.1.1 Self-Service Account Access Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add bounded self-service email recovery, six-digit email sign-in,
and a truthful globally accessible sign-out control while preserving password
login, existing sessions, operator recovery, learner behavior, and the v0.1
security boundary.

**Architecture:** Keep the browser -> Node API -> transaction-capable MongoDB
authority boundary. Issue credentials in short Mongo transactions, commit and
end those sessions, make one bounded call through an injected transactional
email provider, then perform a standalone conditional delivery-state update.
Only delivery-acknowledged credentials verify. React owns session state once
above all private routes so the global sign-out control and account screens
share one truthful source of authentication state.

**Tech Stack:** Node.js 24.14.0, pnpm 11.9.0, strict TypeScript, Express 5,
Mongoose 9/MongoDB replica-set transactions, Zod, native `fetch`, React 19,
React Router 8, Vitest, Supertest, Testing Library, Playwright, Docker Compose,
and the existing self-host/release scripts.

**Spec:**
`docs/superpowers/specs/2026-09-13-v0.1.1-auth-access-design.md`

## Global constraints

- Implement only the approved v0.1.1 scope: preserve password login; add
  globally accessible sign out, self-service forgot-password email, and a
  six-digit email sign-in code. Do not add SMS, mandatory passwordless auth,
  OAuth/social login, or unrelated product work.
- Follow strict RED -> GREEN TDD. Add one focused behavioral test, observe it
  fail for the expected missing behavior, write the smallest production change,
  observe it pass, then run the affected neighboring suite before committing.
- Do not weaken the existing Origin, CSRF, cookie, rate-limit, user `writeFence`,
  transaction, account-deletion, export-sanitization, or required-persistence
  boundaries.
- Invalid static production email configuration fails closed at startup.
  Provider construction, `/health`, and `/ready` make no Resend network calls.
  A runtime provider outage must not affect password login, authenticated
  sessions, learner routes, operator reset issuance, or unrelated readiness.
- Never keep a Mongo transaction/session open during provider I/O, provider
  timeout, delivery-state acknowledgement, telemetry, or the 750 ms public
  timing floor. The floor uses an asynchronous promise timer after all database
  and provider work.
- A self-service reset or login code is unverifiable until the authoritative
  conditional `sentAt` transition matches. Provider success followed by a
  zero-match or persistence failure takes the sanitized failure/revocation
  path, never blindly retries, and permits a later bounded issuance.
- Provider idempotency metadata is the fixed `codelift-v1-` prefix plus a
  base64url SHA-256 digest bound to purpose and internal record ID. Never expose
  a raw Mongo ID, user ID, email, reset token, code, or session ID in that key.
- Do not log or persist plaintext login codes, reset URLs/tokens, provider keys,
  the login-code pepper, session cookies, CSRF values, or recipient addresses in
  metrics. The provider destination field is the only permitted recipient copy.
- Automated delivery tests use only the in-memory fake provider or a private
  temporary fake outbox. They never send email or contact Resend.
- Do not perform Resend account changes, DNS changes, production secret
  creation, purchases, or live sends. Stop at
  `EMAIL_PROVIDER_OPERATOR_SETUP_REQUIRED` after all source-only/fake-provider
  work and verification are complete.
- Preserve the v0.1 tag and historical release evidence. Do not rewrite the
  curriculum seed, learning-domain production code, Python service, or existing
  Mongo data.
