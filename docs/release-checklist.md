# Release checklist

This is the reusable operator procedure, not a self-attested status record. The
source-revision-bound `reports/release-quality.json` generated by
`pnpm quality:report` is the release verdict and records every command below.

- [ ] `pnpm install --frozen-lockfile` succeeds on pinned Node/pnpm.
- [ ] Python 3.12 synchronizes from `services/ai/uv.lock` with pinned uv and
      `pnpm python:lock-check` passes.
- [ ] Format, lint, typecheck, unit, integration, Python, and browser gates pass.
- [ ] Production builds and Compose configuration/build pass.
- [ ] `pnpm compose:smoke` passes on fresh named volumes with Python available,
      then stopped, while the API/web remain ready through deterministic fallback.
- [ ] Seed is run twice; idempotent seed and runtime curriculum validation report
      exactly 365 days.
- [ ] Bounded live link report has no static integrity issue.
- [ ] Local behavioral AI eval score is 1.0 with at least 30 executed cases,
      passing negative controls, zero critical failures, no external network call,
      and a source-bound dataset hash.
- [ ] Security check, JavaScript audit, strict Python audit, and HIGH/CRITICAL
      production-image scan pass with no silent waiver.
- [ ] Fresh browser QA covers wide/320px, dark, reduced motion, keyboard,
      errors, RAG citations/abstention, planner approval, and deletion.
- [ ] No secret, personal note, or provider key appears in source/evidence.
- [ ] Threat model, ADRs, runbooks, README, limitations, and quality report match
      the released source digest.
- [ ] Production configuration matrix and `pnpm mvp:check` pass; immutable prompt
      and canonical curriculum are unchanged from the declared baseline.
- [ ] Chromium critical-flow axe scans and the WebKit mobile invite/cookie/Today
      journey pass without raw access tokens in rendered content or evidence.
- [ ] Invite and reset issuance/revocation/replay/concurrency/session-revocation
      tests pass; operator URLs are shared only through an approved channel.
- [ ] Existing password login, global protected-shell sign out, self-service
      Forgot password, and six-digit email sign-in-code journeys pass; SMS,
      OAuth/social login, and fully passwordless conversion remain absent.
- [ ] Known/unknown email requests have identical generic status/body and an
      asynchronous 750 ms floor; request, cooldown, verification, expiry,
      attempt-ceiling, replacement, replay, and single-use tests pass.
- [ ] Email issuance commits before provider/timer work. Both reset and code
      provider-success/database-acknowledgement failure modes leave credentials
      unverifiable, emit sanitized telemetry, and permit bounded re-issuance.
- [ ] A runtime email-provider outage leaves password login, an existing
      session, learner functionality, operator recovery, `/health`, and `/ready`
      working; neither readiness route performs a provider probe.
- [ ] Resend idempotency metadata contains no raw Mongo/user/session ID,
      mailbox, token, or code; only the destination field contains the mailbox
      inherently required for delivery, and the adapter does not blindly retry.
- [ ] Production rejects direct email secret values and the fake provider;
      Resend key and independent login-code pepper are exact API-only mode-0600
      files, while disabled mode retains neither secret.
- [ ] Account export and deletion are tested for tenant scope, derived records,
      secret/hash exclusion, and all-session invalidation.
- [ ] Pilot metrics suppress cohorts below five and contain no learner identity
      or private content; the five research questions and fixed decision
      thresholds are approved.
- [ ] `pnpm fresh-clone:check` passes from the exact clean release revision using
      a no-hardlink local clone, frozen install, Python 3.12 dev install, tests,
      build, curriculum validation, and fresh-volume runtime smoke.
- [ ] Score is at least 95/100 with zero critical failures.
- [ ] Draft PR is reviewed at its evidenced head SHA and required CI is green.

Additional live-pilot gates (cannot be satisfied by source/Compose alone):

- [ ] hosting option, region, domain, exact HTTPS origin, spend ceiling, and
      named release/security/data/incident owners are approved;
- [ ] secret injection, private service routing, readiness rollout, resource
      limits, centralized logs, alert routing, and provider kill switch are
      verified in the named environment;
- [ ] managed Mongo backup policy is active and an isolated restore drill meets
      the approved RPO/RTO with redacted evidence;
- [ ] `pnpm mvp:live-check -- --base-url <https-origin> ...` passes using a
      guarded synthetic account and cleanup is verified;
- [ ] registration remains invite-only, mock AI is active, external AI and
      agents are disabled, and the initial cohort is limited to five.
- [ ] if transactional email is enabled, an authorized operator has verified
      the Resend account, sender/domain and DNS, created the key and independent
      pepper in protected storage without exposing them in chat/history/evidence,
      verified rotation/rollback, and recorded a redacted synthetic live-send;
- [ ] if that email operator setup is incomplete, keep
      `EMAIL_PROVIDER=disabled`, retain operator recovery, and do not describe
      self-service delivery as live.
